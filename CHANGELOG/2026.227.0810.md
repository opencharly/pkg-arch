# 2026.227.0810 — delete the checked-in .SRCINFO

`.SRCINFO` is removed. `PKGBUILD` is now the single source of package metadata
in this repo.

## Why delete rather than regenerate

The file had drifted three separate ways from the `PKGBUILD` beside it:

- `pkgver` said `2026.182.0002`; `PKGBUILD` said `2026.198.1029`
- `tmux` was in `PKGBUILD`'s `depends` and absent here — 24 entries against 23
- it carried a machine-local absolute path checked into git:
  `source = opencharly-git::git+file:///home/atrawog/Sync/Atrapub/av/charly`

Regenerating with `makepkg --printsrcinfo` would fix the first two and
**re-introduce the third**, because the generated file bakes in whatever path
the generating machine used. `CHANGELOG/2026.183.1908.md` records that exact
thing happening once already. A hand-scrub after every regeneration is the R4
environment-specific workaround that would make it happen a third time.

So the divergence class is removed instead of one instance of it.

## Why this is safe

- `README.md:7` states `opencharly-git` is LOCAL-ONLY and NOT published to the
  AUR. `.SRCINFO` exists for AUR consumption; nothing consumes it here.
- No workflow, script, or file in this repository reads `.SRCINFO` — verified by
  a repo-wide grep.
- The superproject's dependency-parity gate (`charly/packaging_test.go:26`)
  reads `../pkg/arch/PKGBUILD` and nothing else, so the parity test is
  unaffected.
- No other reference to `.SRCINFO` exists anywhere in the superproject.

If this package is ever published to the AUR, `.SRCINFO` is regenerated at
publish time from `PKGBUILD` — which is where it should be generated, rather
than committed and left to drift.
