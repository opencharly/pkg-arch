# 2026.279.2039 — fix(pkg-arch): declare conflicts/replaces on the published charly package

## Summary

`pkg-arch`'s `PKGBUILD` declares `provides=('charly')` but **no `conflicts`/`replaces`**, so the install the repo documents — `makepkg -si` (`README.md` "## Install": *"the equivalent one-liner is `cd pkg-arch && makepkg -si`"*) — can never install over the published `charly` package. It aborts on all 29 files both packages own:

```
error: failed to commit transaction (conflicting files)
opencharly-git: /usr/bin/charly exists in filesystem (owned by charly)
opencharly-git: /usr/lib/charly/plugins/plugin-candy exists in filesystem (owned by charly)
... 29 files ...
Errors occurred, no packages were upgraded.
```

`provides` only satisfies a **dependency** on `charly`; it does **not** license pacman to overwrite files owned by it. That authorization is exactly what `conflicts` (plus `replaces`) provides.

This contradicts the repo's own `AGENTS.md` — *"the package must install cleanly on a fresh host"* — and forced an **undocumented manual step** (`sudo pacman -R charly`) that `README.md` never names.

**Change:**
- `PKGBUILD`: add `conflicts=('charly')` and `replaces=('charly')` (with a rationale comment).
- `test-build-path.sh`: two `must` assertions so the defect cannot regress.

Closes (issue): opencharly/pkg-arch#28
